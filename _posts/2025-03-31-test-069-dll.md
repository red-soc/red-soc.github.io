Symbol names are stored in a string table, and each entry points into it by index. The header begins at a fixed offset, so the parser reads a few bytes and validates the magic value first.

## Background

Comparing two builds of the same source showed how much optimization flags change the layout. On Windows the import address table is filled in by the loader before the program starts running.

```c
uint16_t magic = *(uint16_t *)buf;
if (magic != 0x5A4D) {
    fprintf(stderr, "not a PE file\n");
    return 1;
}
```

Every field is little-endian on x86, which matters when you read raw bytes from a file. Reading the specification slowly saved me hours of guessing about reserved fields.
