Padding bytes between fields can differ between compilers, so packed structs need extra care. On Linux the dynamic loader resolves shared library functions lazily through the procedure linkage table.

## Background

I wrote a small C program to dump the structure and compared the output with a hex editor. I kept notes in a cheat sheet so I could check field sizes quickly later. The relocation table lists every place the loader must patch when the image is not mapped at its preferred base.

```c
for (int i = 0; i < nsections; i++) {
    printf("%-8s 0x%08x\n", sec[i].name, sec[i].addr);
}
```

The output looked right at first, but a second sample file exposed an off-by-one error. Writing the parser as a set of small functions made each structure easy to verify separately.

On Windows the import address table is filled in by the loader before the program starts running. Every field is little-endian on x86, which matters when you read raw bytes from a file.
